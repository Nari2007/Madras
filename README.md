# MADRAS V3 — Discord community website
Requires Node.js 22+, no npm dependencies. Run from this folder, not by double-clicking HTML.
1. Copy `.env.example` to `.env` (Windows: `copy .env.example .env`; Linux: `cp .env.example .env`).
2. Open https://discord.com/developers/applications and create/select an app. Copy application/client ID and OAuth2 client secret into `.env`. Create a bot and copy its token privately. Enable Server Members Intent (approval may be required). Install bot into MADRAS with bot scope; if assigning verification roles, grant Manage Roles (not Administrator). Keep bot above the verification role but below staff roles. Register exact OAuth2 redirect `http://localhost:3000/auth/callback` for local testing. For production set PUBLIC_URL to HTTPS website origin and register its `/auth/callback` instead.
3. Enable Discord Developer Mode and copy MADRAS server ID and role IDs. Set DISCORD_GUILD_ID and Discord credentials in `.env`. Set `memberRoleId` and `staffRoles` in `public/config.js`; staff roles are listed in priority order, highest first. Server environment variables MEMBER_ROLE_ID, VERIFIED_ROLE_ID, and STAFF_ROLES can override the public role settings. Use real IDs. Never use a staff role as the member/verified role; ensure it grants no sensitive channel access or moderation privileges. The member role classifies logged-in Discord members. With VERIFIED_ROLE_ID, a logged-in non-pending member must click Verify membership to receive the configured role. This proves control of a Discord account and guild membership, not real-world identity or FiveM whitelist status.
   To show a manually maintained public roster with local profile photos, add entries to `communityProfiles` in `public/config.js`, for example `{ username: 'example', avatar: 'assets/members/1.png', role: 'member' }`; supported roles are `founder`, `member`, and `admin`. Set the corresponding labels in `communityCategories` to customize each section heading. Put the image at `public/assets/members/1.png`. The username must match the Discord username for the signed-in profile to use its local photo.
4. Edit public/config.js for invite, game connection and optional status API. Run `npm start` and visit http://localhost:3000.
5. Deploy to a Node-capable VPS/host with HTTPS reverse proxy. Set PORT and PUBLIC_URL appropriately; do not expose .env, do not use static-only hosting. Run one process; sessions are in-memory and expire after 8 hours or restart. For larger deployment add persistent session storage, edge rate limiting and monitoring. No OAuth tokens are retained. No emails/passwords requested. Staff directory is public, exposes only configured staff display names/avatars/labels; inform staff before publishing. Highest configured role wins, bots and pending members excluded, cache refreshed on demand every 60 seconds; page polls each minute. Staff permissions are not granted by website. Logout does not remove Discord role. Keep secrets private and rotate if leaked.
6. Test login as a non-member, a pending member, an ordinary member and a staff member. Check verification role and directory after Discord role changes. Test on HTTPS before launch.
